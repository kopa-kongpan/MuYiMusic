## 2. 已实现内容

后端：

- 新增 `teachers` 和 `class_schedules` 两张业务表，以及 Alembic migration `20260805_0005`。
- 教师按门店隔离，同一门店教师名称唯一；支持资料、擅长方向、简介、排序和启停。
- 排课保存教师、可选课程商品、课程名称快照、开始与结束时间、容量、已约人数、状态和到课说明。
- 新关联课程商品必须属于当前门店且处于已发布状态；课程名称使用排课快照，不依赖商品后续改名或下架。
- 创建或调整排课时锁定教师记录并检查时段重叠，避免同一教师产生并发冲突。
- 时间必须包含时区，结束时间必须晚于开始时间，新建和调整后的开始时间必须晚于当前时间。
- 排课状态支持 `open`、`closed` 和 `cancelled`；开放与暂停可互相切换，取消为终态。
- 取消已有未来预约的排课会被拒绝，必须先在后续预约模块中处理受影响用户。
- 后台与公开接口单次查询窗口最多 31 天，避免无边界扫描。
- 公开接口只返回启用门店、启用教师、开放、未结束且仍有剩余名额的排课。
- 新增 `schedules:manage` 权限，后台操作同时校验门店授权并写入审计记录。

管理后台：

- 按 `schedules:manage` 权限显示“排课管理”菜单。
- 支持切换授权门店、选择日期，并按教师和状态筛选排课。
- 教师管理支持新增、编辑、排序、擅长方向、简介和启停。
- 排课支持选择启用教师、可选已发布课程商品、课程名称、时段、容量和到课说明。
- 列表展示课程、教师、时段、容量、已约与剩余名额、状态及更新时间。
- 支持编辑、暂停、重新开放和取消；不可逆操作提供明确确认提示。

小程序与 H5：

- 预约页展示当前门店并支持切换门店。
- 提供未来 7 天横向日期选择，按日期读取真实公开排课。
- 展示课程、教师、开始与结束时间、容量和剩余名额。
- 覆盖加载、错误重试、未选择门店和当天无排课状态，并支持下拉刷新。
- 在线预约入口显示为“即将开放”且不可操作，待预约业务规则确认后再接入真实写链路。

## 3. 主要接口

| 方法 | 地址 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET/POST` | `/api/v1/admin/stores/{store_id}/teachers` | `schedules:manage` | 查询或创建教师 |
| `PATCH` | `/api/v1/admin/stores/{store_id}/teachers/{teacher_id}` | `schedules:manage` | 修改或启停教师 |
| `GET/POST` | `/api/v1/admin/stores/{store_id}/schedules` | `schedules:manage` | 查询或创建排课 |
| `PATCH` | `/api/v1/admin/stores/{store_id}/schedules/{schedule_id}` | `schedules:manage` | 调整排课 |
| `POST` | `/api/v1/admin/stores/{store_id}/schedules/{schedule_id}/status` | `schedules:manage` | 开放、暂停或取消排课 |
| `GET` | `/api/v1/app/stores/{store_id}/schedules` | 公开 | 按时间窗口读取可约资源 |

查询接口使用 `starts_from` 和 `starts_before` 指定左闭右开的时间窗口。后台接口可追加 `teacher_id`、`status` 和分页参数；公开接口不接受状态覆盖，公开范围由服务端统一控制。

## 4. 数据与一致性规则

- 所有教师、排课和关联商品均强制校验门店归属，管理员还需具有当前门店授权。
- 教师时间冲突校验在事务内执行，并通过教师行锁串行化同一教师的并发排课写入。
- 排课取消后不能恢复或修改；暂停状态可以修改并重新开放。
- `capacity` 必须为正数且不能小于 `reserved_count`。
- `reserved_count` 当前默认值为 `0`，只允许由下一版预约事务维护，不提供后台直接修改入口。
- 停用教师不会删除历史排课，但对应排课不再进入公开可约结果。
- 历史排课和取消排课保留，不提供物理删除接口。

## 6. 下一版边界

下一版可在书面确认以下规则后实现预约和消课：

- 最早可提前多久预约，以及开课前多久停止预约。
- 用户、教师与排课之间的时段冲突规则。
- 用户取消预约的截止时间、名额释放和课时处理。
- 缺席认定、是否扣课及运营人员处理权限。
- 预约占位时还是消课时扣减课程权益，以及撤销消课的账目恢复规则。

这些规则未确认前，不新增预约成功、取消、缺席或扣课状态，不以客户端判断替代服务端事务与幂等控制。
