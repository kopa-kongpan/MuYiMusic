# MuYiMusic 第七版运营账号与后台运营增强说明

## 1. 版本信息

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.7 运营账号与后台运营增强 |
| 范围依据 | [第一阶段需求规格](./第一阶段需求规格.md) |
| 开发计划 | [第一阶段开发计划](./第一阶段开发计划.md) |
| 状态 | 已完成本地容器验收 |

本版补齐管理后台缺失的子门店运营账号管理，并修正课程商品下架后的状态操作。平台管理员可以创建和维护运营账号，运营账号只能使用授权角色和门店；已下架课程可以重新上架，也可以归档。

## 2. 已确认规则

- 只有同时具备 `platform_admin` 角色和 `admins:manage` 权限的平台管理员可以管理运营账号。
- 运营账号必须绑定一个非 `platform_admin` 角色和至少一个门店。
- 内置 `store_operator` 角色默认拥有 `store_content:manage`、`products:manage`、`users:read`、`schedules:manage`、`appointments:manage` 和 `consumptions:manage`。
- `store_operator` 不默认拥有 `consumptions:reverse`，撤销消课继续由独立授权控制。
- 支持创建、编辑角色与门店授权、启用/停用和重置密码；停用为软停用，保留账号和审计记录。
- 当前登录的平台管理员不能被停用，平台管理员账号不能通过运营账号接口编辑或删除。
- 商品状态允许 `draft -> published`、`published -> offline`、`offline -> published`、`offline -> archived`；已归档商品不可恢复。

## 3. 已实现内容

### 后端

- 新增 `20260805_0007` migration，写入 `admins:manage` 权限、`store_operator` 角色及默认角色权限。
- 新增运营账号列表、角色/门店选项、创建、编辑和重置密码 API。
- 新账号密码使用现有 PBKDF2-SHA256 策略，停用账号无法登录。
- 所有创建、编辑、密码重置和状态变更写入 `audit_logs`，用户名冲突和非法授权返回明确错误。
- 运营账号列表排除平台管理员账号，门店选项只来自数据库已有门店。
- 商品状态服务使用显式允许转换集合，后端拒绝不在状态图中的请求。

### 管理后台

- 新增按 `admins:manage` 权限显示的“运营账号”入口。
- 支持账号分页、用户名搜索、角色展示、授权门店展示、启停开关、编辑和密码重置。
- 已下架商品同时展示“上架”和“归档”两个操作，归档操作给出不可恢复提示。
- 页面覆盖加载、错误、空列表、提交中和无权限状态。

## 4. 主要接口

| 方法 | 地址 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/admin/admin-users` | 平台管理员 | 分页查询运营账号 |
| `GET` | `/api/v1/admin/admin-users/options` | 平台管理员 | 查询可用角色和门店 |
| `POST` | `/api/v1/admin/admin-users` | 平台管理员 | 创建运营账号 |
| `PATCH` | `/api/v1/admin/admin-users/{admin_user_id}` | 平台管理员 | 编辑授权或启停账号 |
| `POST` | `/api/v1/admin/admin-users/{admin_user_id}/reset-password` | 平台管理员 | 重置运营账号密码 |
| `POST` | `/api/v1/admin/stores/{store_id}/products/{product_id}/status` | `products:manage` | 发布、下架、上架或归档课程商品 |

接口沿用统一错误响应、请求 ID、认证和审计约定。OpenAPI 已重新导出，`packages/api-client` 已重新生成。
