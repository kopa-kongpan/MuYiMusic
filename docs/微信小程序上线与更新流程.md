# 微信小程序上线与更新流程

适用项目：MuYiMusic；AppID：`wx30ebb435bb61ba6b`。核对日期：2026-10-20。

## 1. 先区分两种发布

| 改动位置                                                     | 发布方式                                                   | 是否需要微信审核                                             |
| ------------------------------------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------ |
| `services/api/`、数据库迁移、后台任务                        | 发布远程服务器，执行迁移并更新 API / worker                | 单独更新服务端通常不需要；涉及小程序功能变化仍需核对审核要求 |
| `apps/admin/`                                                | 构建并发布远程管理后台静态资源                             | 不需要小程序代码审核                                         |
| H5                                                           | 构建并发布远程 H5                                          | 不通过小程序版本管理发布                                     |
| `apps/miniapp/` 中影响微信端的页面、样式、接口调用或构建配置 | 构建微信代码包 → 开发者工具上传 → 体验版 → 提交审核 → 发布 | 需要                                                         |

**更新服务器不会自动更新用户手机上的小程序代码包。** 本次支付补单、后台确认履约及履约上报属于服务端和管理后台更新，无须为了启用这些能力单独重新提交微信代码包。后续修改小程序页面时，仍需走下面的微信发布流程。

## 2. 首次上线前核对

在 [微信公众平台](https://mp.weixin.qq.com/) 登录这个 AppID 对应的小程序账号：

1. 按后台要求完成主体、认证、备案、服务类目和必要资质；类目、页面内容、实际线下音乐课程服务应一致。
2. 在开发管理的开发设置中核对服务器域名：API 的 request 合法域名为 `https://muyimusic.net`；上传、下载及媒体资源涉及的域名按实际请求分别配置。具体入口名称以当前后台为准。
3. 核对微信支付商户关联、支付权限、交易类小程序相关配置及后台违规通知。**“小程序违规”不能仅靠重新上传代码或服务器部署解除，需要根据平台给出的具体原因整改、申诉并确认限制解除。**
4. 在成员管理中加入负责上传的开发者，以及需要扫码测试的体验成员。
5. 隐私保护指引应与实际收集的信息及调用的接口一致；审核涉及登录、购课时，准备可用的测试路径和平台要求的测试资料。

## 3. 构建生产代码包

在项目根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm check
TARO_APP_API_BASE_URL=https://muyimusic.net pnpm build:weapp
```

生产 API 地址必须显式传入。当前源码默认地址是 `http://127.0.0.1:8080`，不能直接依赖默认值发版。构建完成的微信代码在 `apps/miniapp/dist/weapp/`，不要直接手改构建目录。

如启用订阅消息，构建前还要按平台实际模板设置以下构建变量，并与服务端对应模板保持一致；未开通的模板不要编造 ID：

```text
TARO_APP_WECHAT_TEMPLATE_STUDENT_CANCELLED
TARO_APP_WECHAT_TEMPLATE_NEXT_DAY_REMINDER
TARO_APP_WECHAT_TEMPLATE_TEACHER_NEW_APPOINTMENT
TARO_APP_WECHAT_TEMPLATE_TEACHER_CANCELLED
```

不要把 AppSecret、商户私钥或 API v3 密钥放入小程序代码包。

## 4. 开发者工具上传与体验版验收

1. 使用有开发权限的微信登录微信开发者工具，导入 **`apps/miniapp/`**。该目录内 `project.config.json` 的 `miniprogramRoot` 为 `dist/weapp/`，AppID 应与上文一致。
2. 本地设置中关闭“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”，按生产条件测试。项目配置当前 `urlCheck: false`，开发阶段能访问不代表上线域名已配置正确。
3. 先“编译”“预览”，用安卓和 iPhone 真机测试登录、门店、课程、下单、支付失败提示、订单和已购权益。
4. 点击工具顶部“上传”，填写递增版本号和具体改动说明，例如 `1.0.1` / “完善课程展示与支付异常提示”。版本号以实际线上版本为基准。
5. 到公众平台的“版本管理”找到刚上传的开发版本，设为体验版；加入体验成员后扫码验收。上传成功只生成开发版本，尚未上线。
6. 支付验收应核对微信支付结果、服务端订单及权益三者一致；实际交付课程后，再由有权限的后台人员在用户订单中点击“确认履约”。不要用购买成功代替课程实际完成。

## 5. 提交审核与正式发布

1. 在“版本管理 → 开发版本”选择已验收版本，点击“提交审核”。
2. 按当前审核页面填写服务类目、功能说明、测试步骤、隐私信息及所需资料；需要登录才能访问的功能应提供可执行的审核路径。
3. 等待审核结果。被拒绝时按具体原因整改，重新构建、上传并提交；不要假设固定审核时长。
4. 审核通过后，在审核版本中执行“发布”；若后台提供分阶段发布，可先小范围观察再扩大。**审核通过不等于已经正式发布。**
5. 用普通用户微信从正式入口进入，核对版本、API 域名、下单、支付及后台订单。开发版、体验版与正式版要分别识别，避免扫错码。

## 6. 后续更新与回退

建议顺序：**备份 → 发布兼容旧版客户端的服务端和迁移 → 构建小程序 → 体验验收 → 审核 → 发布 → 观察线上结果**。

微信客户端存在旧版缓存，后台发布后不会立即让全部用户切到新版本；冷启动会检查更新，异步更新可能要下次冷启动才应用。当前 `apps/miniapp/src/app.ts` 尚未接入 `wx.getUpdateManager()` 的更新提示。如以后增加提示，应在新包下载完成后让用户确认重启，并避开正在支付或填写表单的操作。

出现严重问题时，先在公众平台“版本管理”检查可用的回退操作，并验证客户端和接口兼容性。服务端可切回已备份的镜像；数据库迁移是否回退需单独评估，涉及新增订单和支付记录时不能直接恢复旧库覆盖数据。

## 7. 支付失败怎样取证

如首页提示“待接入订单管理－订单信息录入”，还需单独完成微信订单中心跳转配置。
本项目已实现 `pages/order-detail/index?order_no=${商品订单号}`，需先发布包含该页面的新小程序包，再到平台登记。
具体操作、订单号映射及验收记录见[微信订单中心接入说明](微信订单中心接入说明.md)。

安卓真机连接开发者工具的“真机调试”，重现一次失败，记录发生时间、当前版本、订单号和 `errMsg` / `errno` / `errCode`。在 Network 中查看创建支付的请求和响应；请求路径为 `/api/v1/app/orders/{order_id}/payments/wechat`，接口成功仅表示预支付阶段成功，最终以服务端确认支付结果为准。

如果 Console 没有详细错误，目前购物车异常分支主要显示 toast，可在调试代码的支付 catch 中补充错误字段日志再构建调试。不要记录签名、私钥、用户完整身份信息或整段支付参数。

同时查看公众平台和商户平台的违规通知或限制说明。“小程序违规”的精确原因应以平台通知为准，不能仅凭这几个字确定是缺少证书或发货上报。
