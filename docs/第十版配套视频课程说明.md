# MuYiMusic 第十版配套视频课程说明

## 1. 目标与业务规则

课程商品不再区分“线下课时课程”和“视频课程”，所有可售商品统一为线下课时课程，每个启用规格必须配置大于 0 的线下课时数。

后台新增独立“视频课程”页面。视频课程沿用门店现有课程分类，可配置名称、简介、启用状态和多个视频课时；每个课时包含唯一课时序号、标题、一个教学视频、可选时长和启用状态。

线下课程商品可以绑定多个同门店的启用视频课程。每个绑定独立配置以下一种开放方式：

- 全部课时：自动开放该视频课程当前所有启用课时，后续新增启用课时也自动开放。
- 指定课时：只开放绑定时明确选择且仍处于启用状态的课时。

公开课程详情只展示配套视频课程和课时元信息，不返回视频地址。用户在线下成交并获得有效课程权益后，微信侧“我的课程”同时展示线下课时进度与开放的视频课时，并通过短期签名地址播放。权益过期或耗尽后不再返回视频课时及播放地址。

## 2. 数据模型与兼容策略

- `video_courses`：独立视频课程，按 `store_id` 隔离并关联现有 `categories`。
- `video_course_lessons`：视频课时，一个课时对应一个对象存储视频。
- `product_video_course_bindings`：线下课程商品与视频课程绑定，记录 `all` 或 `selected` 开放方式。
- `product_video_course_binding_lessons`：指定开放方式下的课时集合。

数据库保留历史 `product_type` 枚举列以兼容订单、权益快照和旧客户端，但所有新建、更新及发放统一写入 `course`，后台不再提供商品类型选择。

`20260828_0013` migration 会把旧 `video` 商品转换为普通线下课程，将 `product_videos` 迁为独立视频课程课时并建立“全部课时”绑定；原课时数为 0 的 SKU、订单明细和权益会补齐为正课时数，避免历史权益直接变成已用完。

## 3. 管理接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/admin/stores/{store_id}/video-courses` | 分页查询视频课程 |
| `POST` | `/api/v1/admin/stores/{store_id}/video-courses` | 创建视频课程与课时 |
| `GET` | `/api/v1/admin/stores/{store_id}/video-courses/{id}` | 查询视频课程详情 |
| `PATCH` | `/api/v1/admin/stores/{store_id}/video-courses/{id}` | 更新视频课程与课时 |

以上接口沿用 `products:manage` 权限。商品创建和更新接口新增 `video_course_bindings`，服务端校验同门店、课程启用状态、课时归属、开放方式及重复绑定。

## 4. 验收范围

- 独立视频课程支持真实视频上传、创建和更新课时。
- 普通线下课程商品可分别绑定全部课时和指定课时。
- 跨门店视频课程、错误课时编号、重复绑定和无课时的指定开放均被拒绝。
- 公开详情仅返回开放课时元信息，不泄露对象键和签名播放地址。
- 有效权益只返回绑定允许的视频课时；过期或耗尽权益不返回视频课时与播放地址。
- migration 通过从基线升级、`0012 → head`、`head → 0012 → head` 往返验证。
- 本地 Docker 的 migration、管理员初始化和长期服务健康，并通过 `/health`、公开门店 API、管理后台、H5、真实上传与签名下载验收。
