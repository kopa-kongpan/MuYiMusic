# MuYiMusic 本地容器部署说明

## 1. 部署目标

每次功能开发完成并通过代码检查后，必须执行一次完整 Docker 本地部署。部署使用 MuYiMusic 独立的 PostgreSQL、Redis 和数据卷，不依赖本机或其他项目的数据库容器。

Compose 包含以下服务：

| 服务 | 用途 | 本地地址 |
| --- | --- | --- |
| `postgres` | 项目独立 PostgreSQL 17 | `localhost:15432` |
| `redis` | 项目独立 Redis 7 | `localhost:16379` |
| `migrate` | 一次性执行 Alembic migration | 无 |
| `bootstrap` | 一次性同步平台管理员、角色和权限 | 无 |
| `api` | FastAPI 服务 | 通过 Nginx 访问 |
| `nginx` | API 网关 | `http://localhost:8080` |
| `admin` | 管理后台静态站点和 API 代理 | `http://localhost:5173` |
| `h5` | 小程序 H5 预览和 API 代理 | `http://localhost:10086` |

`15432/16379` 是宿主机映射端口；API 容器始终通过 Compose 内部网络连接 `postgres:5432` 和 `redis:6379`。
本地 Conda API 在未显式设置 `DATABASE_URL`、`REDIS_URL` 时，会根据 `.env` 中的 `POSTGRES_*` 和 `DOCKER_*_PORT` 生成宿主机连接地址，避免维护两套密码。

## 2. 首次配置

从 `.env.example` 创建本地 `.env`，至少替换以下值：

- `POSTGRES_PASSWORD`
- `JWT_SECRET`
- `ADMIN_INITIAL_PASSWORD`

`.env` 不得提交 Git。对象存储配置参见 [第二版首页内容闭环说明](./第二版首页内容闭环说明.md)。

## 3. 部署命令

```powershell
pnpm deploy:local
pnpm deploy:status
```

`deploy:local` 会构建 API、管理后台和 H5 镜像，等待 PostgreSQL、Redis 健康后依次执行 migration、管理员初始化并启动长期服务。migration 或初始化失败时，API 不会启动。

查看日志：

```powershell
docker compose --env-file .env -f deploy/compose.yaml logs --tail=200
```

停止服务但保留数据库数据：

```powershell
pnpm deploy:down
```

不得在日常验证中使用 `down -v`，该参数会删除项目数据库和 Redis 数据卷。

## 4. 完成验证

每次部署至少检查：

```powershell
docker compose --env-file .env -f deploy/compose.yaml ps
curl.exe http://localhost:8080/health
curl.exe "http://localhost:8080/api/v1/app/stores?page_size=1"
```

同时访问管理后台和 H5，确认静态资源加载成功且 API 请求不出现网络错误。`migrate` 和 `bootstrap` 应显示退出码 `0`，其余长期服务应为运行或健康状态。

## 5. 数据库确认

查询当前 migration 版本：

```powershell
docker compose --env-file .env -f deploy/compose.yaml exec postgres sh -c `
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select version_num from alembic_version;"'
```

正常情况下应返回仓库最新 revision。数据库数据保存在 Compose 卷 `muyimusic_postgres-local-data` 中，重新构建镜像或执行普通 `down` 不会丢失。
