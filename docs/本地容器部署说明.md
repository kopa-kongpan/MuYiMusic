# MuYiMusic 本地容器部署说明

## 1. 部署目标

每次功能开发完成并通过代码检查后，必须执行一次完整 Docker 本地部署。部署使用 MuYiMusic 独立的 PostgreSQL、Redis 和数据卷，不依赖本机或其他项目的数据库容器。

Compose 包含以下服务：

| 服务 | 用途 | 本地地址 |
| --- | --- | --- |
| `postgres` | 项目独立 PostgreSQL 17 | `localhost:15432` |
| `redis` | 项目独立 Redis 7 | `localhost:16379` |
| `migrate` | 一次性执行 Alembic migration | 无 |
| `bootstrap` | 一次性同步平台管理员、角色和权限 | 无 |
| `api` | FastAPI 服务 | 通过 Nginx 访问 |
| `nginx` | API 网关 | `http://localhost:8080` |
| `admin` | 管理后台静态站点和 API 代理 | `http://localhost:5173` |
| `h5` | 小程序 H5 预览和 API 代理 | `http://localhost:10086` |

`15432/16379` 是宿主机映射端口；API 容器始终通过 Compose 内部网络连接 `postgres:5432` 和 `redis:6379`。
本地 Conda API 在未显式设置 `DATABASE_URL`、`REDIS_URL` 时，会根据 `.env` 中的 `POSTGRES_*` 和 `DOCKER_*_PORT` 生成宿主机连接地址，避免维护两套密码。

## 2. 首次配置

从 `.env.example` 创建本地 `.env`，至少替换以下值：

- `POSTGRES_PASSWORD`
- `JWT_SECRET`
- `ADMIN_INITIAL_PASSWORD`

`.env` 不得提交 Git。对象存储配置参见 [第二版首页内容闭环说明](./第二版首页内容闭环说明.md)。

## 3. 部署命令

```powershell
pnpm deploy:local
pnpm deploy:status
```

`deploy:local` 会构建 API、管理后台和 H5 镜像，并通过
`deploy/compose.local.yaml` 启动本地 MinIO 私有对象存储、自动建桶及配置
CORS。等待 PostgreSQL、Redis、MinIO 健康后依次执行 migration、管理员初始化
并启动长期服务。对象存储初始化、migration 或管理员初始化失败时，API 不会启动。

MinIO API 默认监听 `19000`，管理控制台默认监听 `19001`。本地管理后台
上传的图片和教学视频使用预签名 URL 直传，视频播放也使用限时签名地址；
生产部署不加载本地 Compose overlay，仍由 `.env` 中的 COS/S3 配置决定。

查看日志：

```powershell
docker compose --env-file .env -f deploy/compose.yaml logs --tail=200
```

停止服务但保留数据库数据：

```powershell
pnpm deploy:down
```

不得在日常验证中使用 `down -v`，该参数会删除项目数据库和 Redis 数据卷。

## 4. 完成验证

每次部署至少检查：

```powershell
docker compose --env-file .env -f deploy/compose.yaml ps
curl.exe http://localhost:8080/health
curl.exe "http://localhost:8080/api/v1/app/stores?page_size=1"
```

同时访问管理后台和 H5，确认静态资源加载成功且 API 请求不出现网络错误。`migrate` 和 `bootstrap` 应显示退出码 `0`，其余长期服务应为运行或健康状态。

## 5. 数据库确认

查询当前 migration 版本：

```powershell
docker compose --env-file .env -f deploy/compose.yaml exec postgres sh -c `
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select version_num from alembic_version;"'
```

正常情况下应返回仓库最新 revision。数据库数据保存在 Compose 卷 `muyimusic_postgres-local-data` 中，重新构建镜像或执行普通 `down` 不会丢失。

v0.5 起，最新 revision 应为 `20260805_0005`，并包含 `teachers` 与 `class_schedules` 表。初始化平台管理员应包含 `schedules:manage` 权限。

## 6. 当前验证记录

2026-08-05 已完成 v0.4 完整部署验证：

- PostgreSQL 和 Redis 健康，宿主机端口分别为 `15432` 和 `16379`。
- `migrate` 和 `bootstrap` 退出码均为 `0`。
- API、API 网关、管理后台和 H5 容器启动成功。
- 数据库为 `muyimusic`，Alembic revision 为 `20260805_0004`；用户、平台账号、订单、订单项和课程权益表均存在。
- API 网关、管理后台代理和 H5 代理访问公开门店接口均返回 `200`。
- 管理员登录返回 `200`，初始化平台管理员包含 `products:manage` 和 `users:read` 权限。
- H5 本地用户登录、本人资料、本人订单和本人课程权益 API 均返回 `200`；身份原文在服务端哈希后保存。
- migration 与管理员初始化容器退出码均为 `0`，全部长期服务处于 healthy 状态。

2026-08-05 已完成 v0.5 完整部署验证：

- 全栈镜像重建成功，`migrate` 和 `bootstrap` 退出码均为 `0`，全部长期服务 healthy。
- 数据库 revision 为 `20260805_0005`，`teachers` 和 `class_schedules` 表存在。
- 初始化平台管理员包含 `schedules:manage` 权限。
- `/health`、公开门店 API、管理后台、管理后台排课路由和 H5 均返回 `200`。
- 通过 API 创建带明确标记的本地验收门店、教师和排课后，API 网关、管理后台代理与 H5 代理均能读取同一数据库排课，公开余量计算正确。
