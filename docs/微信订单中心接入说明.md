# 微信订单中心接入说明

本次接入对应微信公众平台的「待接入订单管理－订单信息录入」通知。
订单中心跳转、发货信息管理和交易结算管理确认是不同配置项，后两项查询通过并不表示订单详情 Path 已登记。

## 需要登记的 Path

```text
pages/order-detail/index?order_no=${商品订单号}
```

完整复制上面的内容，保留中文占位符 `${商品订单号}`，不加开头的 `/`。
它是小程序页面路径，不是网站或 API 地址。

先上传包含该页面的新小程序包，完成体验验收、审核及正式发布，再在微信公众平台的
「订单管理 → 订单信息录入」中登记此 Path。首次进入时，按实际业务确认“同意并接入”及页面提示。
登记成功与支付限制解除需要分别核实，不能仅凭服务器部署成功认定微信限制已解除。

如平台另行要求填写“小程序订单中心 Path”（列表入口），使用 `pages/my-orders/index`；
不要用列表入口代替带商品订单号的单笔详情 Path。

## 已实现的链路

- JSAPI 下单的 `description` 使用订单成交快照中的商品名、规格和数量，最多 127 个字符；
  例如“钢琴进阶考级课 10次卡 ×1”。已有预支付订单不会被本次发布重写。
- 微信用下单的 `out_trade_no` 替换 `${商品订单号}`。项目中它对应 `payments.merchant_order_no`，
  与 `orders.order_no` 不同，详情接口同时支持两种编号。
- 新增 `GET /api/v1/app/me/orders/{order_number}`，必须登录，仅查询当前用户的订单；
  不受客户端当前选择的门店影响。他人的编号和不存在的编号均返回 404。
- 微信冷启动详情页时，通过微信登录恢复本人身份，不强制绑定手机号、填写头像或昵称。
  登录失败可重试或进入“我的”登录后返回详情。
- 详情展示商品成交快照、规格、数量、金额、订单及支付状态、下单/支付时间、所属门店和售后电话。
  “我的订单”增加“查看订单”入口。
- 退款状态优先于业务订单的“已确认”，已支付记录不会被后续已关闭的支付尝试遮蔽。
- 售后入口拨打订单所属门店电话；未增加自动退款或自动确认课程已交付。

## 构建与验收

```bash
pnpm check
TARO_APP_API_BASE_URL=https://muyimusic.net pnpm build:weapp
```

开发者工具导入 `apps/miniapp/`，编译入口设置为新详情页，参数使用本人订单的实际商户支付单号。
依次检查：已登录打开、无登录冷启动、已切换其他门店、已退款、他人订单以及不存在的订单。
确认商品、金额和售后联系方式正确，再上传并发布。

登记 Path 后，通过微信的订单入口打开一笔真实订单，核对是否直接进入该订单详情。
实际履约完成后仍需按业务事实确认履约；订单中心跳转不能代替履约上报。

## 发布边界

本次服务端无新增数据库迁移，仍为 `20261019_0016`。远端发布需先备份数据库及原镜像/源码，
