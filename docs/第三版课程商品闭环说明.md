## 2. 已实现内容

后端：

- 新增 `categories`、`products`、`product_skus`、`product_images` 四张业务表和 Alembic migration `20260804_0003`。
- 商品金额统一使用整数分；SKU 包含售价、课时数、有效天数、排序和启停状态。
- 商品严格按 `draft -> published -> offline -> archived` 流转，归档后不可修改或恢复。
- 只有门店启用、分类启用、商品已发布、销售时间有效且至少存在一个启用 SKU 时，公开接口才返回商品。
- 支持分类维护和排序、商品分页、关键词搜索、分类/状态筛选、预览、编辑和状态流转。
- 公开课程支持综合、销量、最新、价格升序和价格降序排序。
- 购买前校验重新读取门店、分类、商品、SKU、数量和实时价格，返回当前单价与总价，不创建订单。
- 新增 `products:manage` 权限，所有分类和商品写操作记录审计日志，并强制管理员门店授权范围。
- 上传凭证新增 `product` 用途，商品只允许图片，object key 固定在 `stores/{store_id}/products/` 门店目录下。

管理后台：

- 新增按 `products:manage` 权限显示的“课程商品”菜单。
- 支持门店切换、商品搜索、分类和状态筛选、分页及刷新。
- 分类维护支持创建、修改名称、启停和上下移动排序。
- 商品表单支持分类、名称、摘要、详情、购买须知、销售时间、封面、图集和动态 SKU。
- 金额按元录入，提交时转换为整数分；商品媒体使用对象存储直传。
- 商品列表提供预览、编辑、发布、下架和归档操作，按钮状态与后端流转规则一致。

小程序：

- 课程页支持分类、关键词搜索、五种排序、下拉刷新、分页加载及加载/空/错误状态。
- 课程详情展示商品图片、课程内容、购买须知、SKU、数量和实时总价。
- 加入购物车和立即购买前均调用购买校验接口；立即购买按已确认边界进入购物车。
- 购物车按当前门店存储，切换门店不会混用商品。
- 修改购物车数量和手动更新价格时重新调用购买校验接口，实时价格覆盖本地价格。
- 不展示模拟订单、支付成功或课程权益数据。

接口契约：

- FastAPI OpenAPI 已重新导出，`packages/api-client` 已生成最新类型。
- 共享客户端提供后台分类/商品接口和公开分类/课程/购买校验接口。
- 管理后台与小程序均使用生成的数据类型，不重复维护 DTO。

## 4. 数据与状态规则

商品状态只能按以下方向推进：

```text
草稿 draft -> 已发布 published -> 已下架 offline -> 已归档 archived
```

- 发布时分类必须启用、媒体必须属于当前门店，并至少存在一个启用 SKU。
- SKU 从商品表单移除时只停用，不物理删除，为后续订单历史引用保留稳定标识。
- 商品图集可以替换；数据库只保存 object key，访问地址由对象存储配置生成。
- 分类停用后，该分类下已发布商品立即从公开接口隐藏，但后台数据和状态不变。
- 销售开始时间包含边界，销售结束时间不包含边界。

## 5. 与原计划的差异

原 P3 描述包含“订单基础模型”。本版将订单模型调整到 P4，与用户和课程权益一起建立，原因如下：

- 第一阶段尚未实现小程序用户身份，P3 创建订单会产生无所有者的伪业务数据。
- 订单需要同时确定用户归属、课程权益发放、支付边界和历史价格快照，拆开建立会导致模型反复迁移。
- P3 已通过购买校验固定实时商品、SKU、数量和金额契约，P4 可在该契约之后原子创建订单和权益。

这一调整不影响 P3 的公开浏览和购物车验收，也不以模拟订单掩盖未完成功能。

## 7. 下一版边界

P4 将建立真实小程序用户、订单和课程权益：订单保存购买时价格快照并关联用户，支付方案确认后再接支付与回调。P4 不应直接复用购物车本地价格创建订单，仍须在服务端事务中完成最终校验。
