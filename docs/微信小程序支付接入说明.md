# 微信小程序支付接入说明

## 已确认配置

- 小程序 AppID：`wx30ebb435bb61ba6b`
- 微信支付商户号：`1750778977`
- 收款模式：全部门店统一进入同一普通商户号
- 支付方式：微信支付 API v3 JSAPI/小程序支付
- 支付通知地址：`https://muyimusic.net/api/v1/webhooks/wechat-pay`

原生 App 支付的 `/v3/pay/transactions/app` 不适用于本项目。服务端使用
`/v3/pay/transactions/jsapi` 下单，小程序使用 `wx.requestPayment` 调起收银台。

## 配置与密钥

复制 `.env.example` 为本地 `.env` 后填写以下配置：

```dotenv
WECHAT_APP_ID=wx30ebb435bb61ba6b
WECHAT_APP_SECRET=
WECHAT_PAY_MCH_ID=1750778977
WECHAT_PAY_MERCHANT_SERIAL_NO=
WECHAT_PAY_PRIVATE_KEY_PATH=/run/secrets/wechat_pay_private_key.pem
WECHAT_PAY_API_V3_KEY=
WECHAT_PAY_PUBLIC_KEY_ID=
WECHAT_PAY_PUBLIC_KEY_PATH=/run/secrets/wechat_pay_public_key.pem
WECHAT_PAY_NOTIFY_URL=https://muyimusic.net/api/v1/webhooks/wechat-pay
WECHAT_PAY_ORDER_EXPIRE_MINUTES=30
```

把商户 API 私钥保存为：

```text
deploy/secrets/wechat_pay_private_key.pem
```

把微信支付公钥保存为（也兼容把微信支付平台证书 PEM 放在该路径）：

```text
deploy/secrets/wechat_pay_public_key.pem
```

`deploy/secrets/` 以只读方式挂载到 API 容器的 `/run/secrets/`。所有 PEM、`.env`、
AppSecret 和 API v3 密钥均被 Git 忽略，不得复制进镜像、源码或项目文档。

## 业务链路

1. 小程序用户通过微信登录，服务端保存当前小程序 AppID 下的 `openid`。
2. 购物车提交 `POST /api/v1/app/orders`，服务端重新校验门店、商品、SKU、销售
   时间和实时价格，创建待支付订单及价格快照。
3. 小程序调用 `POST /api/v1/app/orders/{order_id}/payments/wechat`。
4. 服务端创建本地支付单，调用微信 JSAPI 下单并返回 `wx.requestPayment` 参数。
5. 小程序调起微信收银台。客户端成功结果不直接确认订单。
6. 微信向 `/api/v1/webhooks/wechat-pay` 发送支付通知；服务端先验签，再使用 API
   v3 密钥解密通知，校验 AppID、商户号、商户订单号和金额。
7. 服务端在数据库事务内确认支付、更新订单、发放课程权益并增加商品销量。
8. 小程序主动调用查单接口补偿回调延迟，只有订单变为 `confirmed` 后才清空购物车。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/app/orders` | 幂等创建待支付订单 |
| `POST` | `/api/v1/app/orders/{order_id}/payments/wechat` | 创建或复用微信预支付 |
| `POST` | `/api/v1/app/orders/{order_id}/payments/wechat/query` | 服务端向微信主动查单 |
| `POST` | `/api/v1/webhooks/wechat-pay` | 微信支付通知 |

## 安全与幂等

- 订单金额只使用服务端实时价格计算，忽略客户端展示金额。
- 创建订单要求 `Idempotency-Key`，重复请求返回原订单。
- 一个订单可以产生多个支付尝试，每个商户订单号全局唯一；数据库约束同一订单
  同时最多存在一条 `pending` 支付。
- 支付通知和主动查单共用同一行锁与确认逻辑，不会重复发放课程权益。
- 旧支付尝试迟到成功时，会确认订单并主动关闭同订单的其他待支付尝试；若微信已
  将其他尝试也扣款成功，服务端会记录第二笔交易并输出最高级别日志，供退款对账。
- 支付成功以服务端通知或主动查单为准，不信任 `wx.requestPayment` 客户端结果。
- 微信响应与通知必须使用微信支付公钥验签，通知密文必须使用 API v3 密钥解密。

`WECHAT_PAY_PUBLIC_KEY_ID` 应填写响应头 `Wechatpay-Serial` 对应的验签材料标识：
使用微信支付公钥时填写 `PUB_KEY_ID_...`，使用平台证书时填写证书序列号。不要把
商户 API 证书序列号误填到这里。

## 联调要求

- `https://muyimusic.net` 必须能从公网以 HTTPS 访问支付通知路径。
- 小程序后台必须配置生产 API 请求合法域名。
- 商户号必须已经关联该小程序 AppID，并开通 JSAPI/小程序支付。
- 真机支付使用真实微信用户测试；不得使用 H5 本地模拟身份发起微信支付。
- 联调后检查订单、支付单、课程权益和商品销量是否一致，并重复发送同一通知验证
  幂等性。
