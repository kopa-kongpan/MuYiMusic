# 商品图片归属修复说明

## 原因

早期演示数据的商品封面和图集使用 `seed/...` 路径，不符合现有的门店归属校验。
编辑已发布商品时会校验封面和全部图集，因此会出现“商品封面不属于当前门店”。
商品图片应位于 `muyimusic/stores/<门店 UUID>/products/` 下。

种子生成器现为封面和图集生成带门店目录的路径，例如
`muyimusic/stores/<门店 UUID>/products/seed/cover-piano-a.png`。
生成器中的占位路径仍需配套真实图片；仅执行 SQL 不会上传文件。

## 修复已有演示商品

在 API 的 Python 环境中先预览：

```bash
python -m scripts.repair_product_media_keys
```

确认后执行，并保留备份文件：

```bash
python -m scripts.repair_product_media_keys --apply --backup /tmp/product-media-before.json
```

工具只处理 `seed/...` 的商品封面和图集，不改动正常上传的图片或其他门店目录。
存在的原图片会复制到所属门店目录，原对象保留；全部复制成功后在一个数据库事务中更新引用。
再次运行不会重复修改已修复引用，已有备份文件也不会被覆盖。

如果历史种子只有占位引用、对象存储内本来就没有对应文件，可明确添加
`--allow-missing` 修正占位引用，随后在后台上传真实封面和图集。
不存在的旧图片会在输出的 `missing` 列表中列出，工具不会伪造图片。
通过容器内部地址访问 S3 时，可使用 `--storage-endpoint http://minio:9000`；
本地 LocalStack 的容器内部端口为 `4566`。

## 线上 MinIO 上传入口

浏览器使用的 `OBJECT_STORAGE_ENDPOINT` 必须是可访问的 HTTPS 地址，不能指向用户电脑的
`localhost`。当前线上应配置为 `https://muyimusic.net`，并在 HTTPS 站点配置中增加存储桶代理：

```nginx
location ^~ /muyimusic-prod/ {
    client_max_body_size 200m;
    proxy_pass http://127.0.0.1:19000;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_request_buffering off;
    proxy_buffering off;
}
```

保留原始 Host 和请求路径，确保 S3 预签名校验正常。
如果旧部署仍加载 `compose.local.yaml`，需最后叠加
`deploy/compose.storage-public.yaml`，使 API 和 worker 使用 `.env` 中的公网地址。
仅更新已有 API 和 worker 时使用 `up -d --no-build --no-deps api worker`。
切换前备份站点配置、环境文件和待修改的数据；图片修复保留独立 JSON 备份。
