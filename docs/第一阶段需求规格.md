## 2. 阶段目标

第一阶段交付门店制音乐课程小程序和对应的 Web 运营管理后台，形成以下核心闭环：

1. 用户选择门店并进入对应门店首页。
2. 用户浏览门店介绍、图片、视频和课程商品。
3. 用户查看课程详情并发起购买。
4. 已有课程权益的用户按门店、课程类型和日期预约课程。
5. 运营人员维护门店、首页内容、课程商品、排课、预约和消课记录。

## 3. 范围分级

### 3.1 PDF 明确要求

- 门店列表、地图定位、门店搜索、距离显示、联系门店和进入门店。
- 首页以图片和视频展示门店内容。
- 首页快捷入口，包括课程介绍、学员点评、师资团队和特惠活动。
- 课程分类、搜索、排序、列表和课程详情。
- 课程预约，区分团体课和私教课，并按日期展示可预约资源。
- 个人中心及登录入口。
- 后台维护门店地址、首页介绍、商品分类、商品上下架、商品详情、约课和消课。

### 3.2 工程必需能力

以下能力虽未在 PDF 中展开，但属于上述功能可安全运行的必要条件：

- 小程序用户登录、门店上下文和会话管理。
- 管理员登录、角色权限和敏感操作审计。
- 统一错误响应、请求追踪 ID、日志和输入校验。
- 图片与视频上传、存储和访问控制。
- 订单、课程权益、预约和消课的数据一致性及幂等控制。

### 3.3 第一阶段不实现

- 作业/日志、我的评价、卡券中心、直播和活动中心。
- 在线支付、订单取消、退款和发票。
- 课程权益转赠、冻结、延期和跨门店使用。
- 实体乐器销售。
- 抖音小程序发布。代码保留平台适配层，第一阶段先交付微信小程序。

## 4. 用户与角色

| 角色    | 主要能力                            |
| ----- | ------------------------------- |
| 游客    | 选择门店、浏览首页、课程列表和课程详情             |
| 小程序用户 | 登录、查看订单与课程权益、预约课程、查看预约记录、取消课程预约 |
| 门店运营  | 维护授权门店的内容、课程、排课、预约和消课           |

## 5. 核心业务概念

| 概念   | 定义                             |
| ---- | ------------------------------ |
| 门店   | 用户浏览、购买、约课和消课的业务归属单位           |
| 课程商品 | 可购买的课程套餐，包含名称、分类、价格、课时数、有效期和详情 |
| 课程权益 | 用户完成有效购买后获得的可用课时及有效期           |
| 排课   | 某门店在指定日期、时段、课程类型和教师下提供的可预约资源   |
| 预约   | 用户使用课程权益预占一个排课名额               |
| 消课   | 课程完成后扣减用户有效课时并形成不可静默删除的业务记录    |

| ------------ | ----------------------------------- |

| MP-STORE-002 | 页面展示当前位置或当前城市，并支持按关键词搜索门店。          |
| MP-STORE-003 | 地图展示门店位置，列表展示门店名称、营业状态、地址和用户距离。     |

## 8. 建议数据边界

第一阶段预计涉及以下核心数据实体，最终字段以数据库设计和 Alembic migration 为准：

- 门店：`stores`。
- 首页内容：`store_content_blocks`。
- 课程分类和课程商品：`categories`、`products`、`product_skus`、`product_images`、`product_videos`。
- 用户和平台账号：`users`、`provider_accounts`。
- 管理员与权限：`admin_users`、`roles`、`permissions`、`audit_logs`。
- 订单：`orders`、`order_items`。
- 课程权益：`course_entitlements`。
- 教师和排课：`teachers`、`class_schedules`。
- 预约和消课：`appointments`、`lesson_consumptions`。

所有业务数据必须包含明确的门店归属。金额使用最小货币单位整数，时间以带时区 UTC 保存。

## 9. 状态与一致性要求

### 9.1 商品状态

`draft -> published -> offline -> archived`

- 只有 `published` 可在小程序展示和购买。
- `archived` 不可重新销售，但历史订单仍可查询。

### 9.2 预约状态

状态为 `reserved`、`cancelled`、`completed` 和 `no_show`。预约和用户取消截止时间均为开课前 2 小时；同一用户不得预约重叠时段；预约锁定一节课程权益但不扣减，取消释放名额和锁定课时。课程结束后正常到课与缺席均扣减一节，撤销消课恢复课时并保留原消课记录与原因。

### 9.3 一致性

- 预约占位、名额扣减和权益校验必须在同一事务边界内完成。
- 购买、预约和消课接口必须支持幂等键。
- 订单、预约、消课和撤销记录不得通过普通后台操作物理删除。
- 所有敏感后台写操作必须记录审计日志。

## 10. 非功能要求

- 第一阶段先交付微信小程序；平台差异仍通过 `platform` 适配层实现，页面不得散落平台判断。
- API 使用 `/api/v1` 前缀，OpenAPI 是前后端接口契约的唯一来源。
- 列表接口支持分页、查询和排序；前端提供加载、空、错误和重试状态。
- 图片和视频使用对象存储直传，数据库保存对象 key，不保存临时签名 URL。
- 教学视频采用私有对象存储；公开课程接口不得返回播放地址，只有有效权益接口可返回短时签名地址。
- 日志不得记录 access token、完整手机号或支付密钥。
- 关键业务必须覆盖成功、无权限、无库存/名额、重复提交和状态冲突测试。

## 11. 第一阶段验收主流程

1. 管理员创建并启用门店，配置地址和地图坐标。
2. 管理员为门店配置首页图片/视频和快捷入口，小程序展示顺序一致。
3. 管理员创建课程分类与课程商品并上架。
4. 用户选择门店，浏览首页、课程列表和课程详情。
5. 用户登录后可将课程加入购物车，不进入在线支付流程。
6. 管理员创建教师排课。
7. 用户选择日期和可预约资源，预约成功后名额正确变化。
8. 管理员完成消课，用户剩余课时正确扣减且审计记录完整。
9. 重复预约或重复消课请求不会产生重复数据或重复扣减。
10. 门店、商品或排课停用后，小程序按状态正确隐藏或提示。
11. 管理员创建视频课程、上传并绑定教学章节，上架后未购买用户只能看到章节预览。
12. 管理员在线下成交后为用户开通视频课程权益，用户在微信“我的课程”可观看；其他用户或失效权益无法取得播放地址。

## 12. 已确认产品决策

| 主题 | 第一阶段决策 |
| --- | --- |
| 发布平台 | 先交付微信小程序，抖音适配后续启用。 |
| 地图 | 优先使用可满足商用要求的免费地图服务；v0.1 先保存经纬度并支持门店选择。 |
| 门店隔离 | 订单、课程权益和预约均按门店隔离，不跨门店共享。 |
| 课程范围 | 支持教材、视频课程和线下课程，不销售实体乐器。 |
| 交易范围 | 只实现购物车，不实现在线支付、订单取消、退款和发票。 |
| 视频购买认定 | 第一阶段以管理员在线下成交后开通的有效课程权益为准；加入购物车不等于已购买。 |
| 视频访问控制 | 未购买用户仅看章节元信息；有效权益用户通过限时签名地址观看，不公开对象 key。 |
| 课程权益 | 不实现转赠、冻结、延期或跨门店使用。 |
| 预约类型 | 暂不区分团体课与私教课。 |
| 预约截止 | 开课前 2 小时停止预约。 |
| 用户取消 | 开课前 2 小时可取消，取消释放名额与锁定课时。 |
| 时段冲突 | 同一用户不得预约时间重叠的课程。 |
| 课时扣减 | 预约只锁定课时；课程结束后正常到课和缺席均扣减 1 节。 |
| 撤销消课 | 必须有独立权限和原因，保留原记录并恢复课时。 |
| 消课 | 由门店单方面发起，操作前显示明确提示，操作后需要通知用户。 |
