本版在已确认的预约细则下完成 P5 剩余链路。预约只锁定一个课时，不在预约时扣减；正常到课和缺席均在课程结束后扣减，撤销消课会恢复课时并恢复为待处理预约。

## 2. 已确认规则

- 预约和用户取消的截止时间均为开课前 2 小时，由 `BOOKING_CUTOFF_MINUTES` 与 `CANCELLATION_CUTOFF_MINUTES` 配置，默认均为 `120`。
- 同一用户不能预约时间重叠的两个排课。
- 排课必须关联同门店、已发布课程商品；用户权益必须同属用户、门店和商品，且在上课时段有效并有可用课时。
- 预约会增加排课 `reserved_count` 和权益 `reserved_lessons`；`remaining_lessons` 不变。
- 用户取消与管理员取消都会释放一个名额和一个锁定课时。管理员取消必须填写原因。
- 课程结束后，正常到课和缺席都会扣减一个剩余课时并释放对应锁定课时；缺席按扣课处理。
- 撤销消课必须有独立权限和原因；原消课记录改为已撤销并保留，权益恢复一个剩余课时和一个锁定课时，预约回到待处理状态。
- 预约、取消、消课、缺席和撤销均要求 `Idempotency-Key`；用户、排课和权益在事务内行锁，容量和课时约束由数据库兜底。

- 已预约排课禁止修改教师、课程商品、时段和容量；取消排课前必须先处理现有预约。

- 新增按权限显示的“预约与消课”工作台，支持门店、日期、状态和关键字筛选。
- 列表展示学员、预约号、课程、教师、上课时段、权益可用/锁定/剩余课时及预约状态。
- 根据权限和预约状态提供管理员取消、正常消课、缺席扣课和撤销消课；取消与撤销要求填写原因。
- 登出时清除 React Query 缓存，避免不同管理员之间短暂显示旧账号数据。

小程序与 H5：

- 预约页按后端开放状态展示“登录预约”“预约”“已满员”或“已截止”，提交时自动完成平台登录并继续原操作。
- 新增真实“我的预约”和“我的课表”，支持下拉刷新；用户可在截止前取消预约。
- 我的课程展示可用、锁定和总剩余课时；未登录入口成功登录后返回原页面。
- 首页和预约页使用请求序号避免门店或日期切换后旧响应覆盖新数据。
- 课程分享链接和 H5 复制内容携带 `storeId`，接收方会恢复对应门店后加载课程。

## 4. 主要接口

| 方法 | 地址 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/api/v1/app/schedules/{schedule_id}/appointments` | 用户令牌 | 创建预约 |
| `GET` | `/api/v1/app/me/appointments` | 用户令牌 | 查询我的预约 |
| `POST` | `/api/v1/app/me/appointments/{appointment_id}/cancel` | 用户令牌 | 用户取消预约 |
| `GET` | `/api/v1/admin/stores/{store_id}/appointments` | `appointments:manage` | 查询门店预约 |
| `POST` | `/api/v1/admin/stores/{store_id}/appointments/{appointment_id}/cancel` | `appointments:manage` | 管理员取消预约 |
| `POST` | `/api/v1/admin/stores/{store_id}/appointments/{appointment_id}/consume` | `consumptions:manage` | 正常消课 |
| `POST` | `/api/v1/admin/stores/{store_id}/appointments/{appointment_id}/no-show` | `consumptions:manage` | 缺席扣课 |
| `POST` | `/api/v1/admin/stores/{store_id}/consumptions/{consumption_id}/reverse` | `consumptions:reverse` | 撤销消课 |

所有写接口均需请求头 `Idempotency-Key`。接口错误沿用统一 `code`、`message` 和 `request_id` 响应结构。
