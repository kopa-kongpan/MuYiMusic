# 微信小程序手机号绑定说明

## 目标

用户通过微信登录后，在“我的”页面主动授权手机号。服务端把微信返回的手机号绑定到当前用户，门店管理员随后可输入完整手机号查找该用户并开通课程权益。

手机号授权不会替代微信登录：微信登录负责识别账号，手机号负责把该账号与线下学员资料对应起来。

## 微信公众平台准备

1. 小程序主体需要满足微信“手机号快速验证组件”的开放条件。个人主体通常不可使用，具体资格、调用额度和费用以[微信官方文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)及公众平台后台为准。
2. 在小程序管理后台的《用户隐私保护指引》中声明收集手机号的用途，并在提交审核前完成配置。
3. 体验版或正式版必须使用与服务端 `WECHAT_APP_ID`、`WECHAT_APP_SECRET` 对应的同一个小程序。开发者工具应关闭本地模拟登录，使用真实微信登录链路。
4. 用户必须点击“绑定手机号”按钮并主动同意。微信不允许在页面加载时静默读取手机号。

## 已实现流程

1. 小程序调用微信登录，服务端按 `openid` 创建或读取用户并签发用户令牌。
2. “我的”页面在手机号为空时显示“绑定手机号”按钮，按钮使用 `open-type="getPhoneNumber"`。
3. 用户同意后，小程序把事件中的一次性 `code` 发送到 `POST /api/v1/app/me/phone`。
4. API 使用小程序 `access_token` 调用微信 `phonenumber.getPhoneNumber`，读取纯手机号并绑定到当前用户。
5. 管理后台可在门店用户列表中输入完整手机号找到该用户。即使用户尚无订单或课程权益，也可以先被找到并办理线下开课。

微信手机号授权 `code` 有效期短且只能使用一次。授权失败时应由用户重新点击按钮，不应缓存或重放旧 `code`。

## 数据与冲突处理

- `users.phone` 已有唯一约束，因此不需要新增数据库迁移。
- 同一账号再次授权相同手机号会返回成功。
- 手机号已经属于另一个账号时返回 `409`，界面提示用户联系门店处理，不自动合并两个账号。
- 管理后台只有在输入完整的 6 至 20 位数字时，才能找到尚未与当前门店发生业务关系的用户；模糊搜索仍然只查询当前门店已有用户。
- 管理后台接口只返回脱敏手机号，日志不得记录完整手机号、用户令牌、微信密钥或手机号授权 `code`。

## 真机验收

1. 构建小程序时设置 `TARO_APP_API_BASE_URL=https://muyimusic.net`，并把 `apps/miniapp` 导入微信开发者工具；该目录的 `project.config.json` 已把小程序根目录指向 `dist/weapp`。
2. 确认微信公众平台已把 `https://muyimusic.net` 配置为 request 合法域名。
3. 用体验版或真机打开“我的”，完成微信登录，再点击“绑定手机号”。
4. 绑定成功后页面显示手机号；退出并重新登录后仍能显示。
5. 在管理后台选择目标门店，输入完整手机号，确认能找到该用户并可继续开通课程权益。
6. 取消授权、重复点击旧授权码以及使用已绑定到其他账号的手机号时，确认页面给出明确提示。
